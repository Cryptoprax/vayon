# Product Bible v1.0 - mandatory completion gate

The product scope is frozen. This addition changes the definition of completion; it does not authorize features, pages, services, repositories, schemas, APIs, or redesigns.

A workflow is complete only when a real customer completes it end to end without assistance. Every future completion decision must establish all seven conditions:

1. Compiles.
2. Passes tests.
3. Works in production.
4. Can be completed by a first-time customer.
5. Requires no technical knowledge.
6. Requires no documentation.
7. Requires no support call.

Any missing condition means the workflow is not complete. Record the entry point, navigation, permissions, success, failure, recovery, next action, environment, role, evidence date, and observed customer outcome. Never substitute local technical checks for production/customer evidence.

Use only Certified, Blocked, Needs Verification for workflow status. Certified requires the complete evidence set. Blocked identifies a demonstrated missing or contradictory step. Needs Verification means the evidence is incomplete without a demonstrated blocker. Never invent completion, delivery, role persistence, timing, or customer success.

No new implementation work is authorized by this gate. Follow the existing scope rules for reconnection, fixes, clarification, certification and documentation.
