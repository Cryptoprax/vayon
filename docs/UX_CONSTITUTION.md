# VAYON UX Constitution

Every VAYON experience must make the next useful action obvious while keeping customers in control.

## Product rules

1. Never ask twice. Reuse trusted account and business context.
2. Detect automatically. Infer safe defaults such as locale, timezone, language, and currency.
3. Recommend everything. Present one recommended path when several valid paths exist.
4. Hide advanced settings. Reveal specialist controls only when explicitly requested.
5. One primary action. Each screen must have one visually dominant next step.
6. Fewer than five inputs per screen. Prefer cards, choices, templates, and inferred values.
7. Setup under 60 seconds. Optional configuration belongs after first value.
8. Never expose technical terminology to normal users. Provider and runtime details belong in Advanced or Developer settings.
9. AI should always guide. Offer a relevant one-click action without requiring prompt writing.
10. Reduce clicks every sprint. New work must document clicks added, removed, or consolidated.

## Review questions

- Can a first-time user understand the page in five seconds?
- Does the page answer “What should I do next?”
- Can any field be inferred, removed, or converted to a choice?
- Is there exactly one primary action?
- Are advanced controls progressively disclosed?
- Is the experience keyboard accessible, responsive, and respectful of reduced-motion preferences?
- Does personalization remain workspace-safe and avoid exposing private data?

## Enforcement

Sprint UX audits and regression tests enforce the shared onboarding, adaptive workspace, global Create, progressive disclosure, accessibility, and responsive contracts. Authenticated browser review remains required before release.
