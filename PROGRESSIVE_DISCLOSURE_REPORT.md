# Progressive Disclosure Report

| Surface | Default view | Revealed when relevant | Retained behavior |
|---|---|---|---|
| Sidebar | Daily workflow groups and current group's ordinary destinations | Templates, brand assets, publishing calendar, automation rules, AI goals, workflow templates and detailed analytics under More tools for this workflow | Same catalog and role/visibility filter; current advanced destination expands its disclosure |
| AI navigation | No proactive AI group outside the existing AI workflow | Existing AI group when a matching AI path is active | All authorized destinations remain searchable; no AI page or engine added |
| Universal Bar | Search and actions | General AI Assistant tab only within existing AI/intelligence workspaces | Existing commands and record-context launchers retained; stale Ask state falls back to search outside AI context |
| Idle search suggestions | Broker tasks and permitted destinations | Growth/platform suggestions only in their corresponding paths; morning AI brief only in AI context | Existing local history and permitted-record filtering reused |
| Floating Create | Existing ordinary creation actions, secondary visual treatment | Creative actions within creative or property-record context | Existing permission gates retained; button does not compete as the page's primary action |
| Record workspace | One existing usable primary action | Other usable links under More actions | Duplicate command bar and dead-anchor inner sidebar removed; placeholder actions are not promoted |
| Dashboard | Start today's work, business figures, setup, agenda and activity | Existing AI task overview inside a native details element | No new dashboard, KPI logic, service calls or AI capability |
| Campaigns | One Create Campaign entry per data state | Campaign template choices in a disclosure | Same wizard callbacks and generation limitations |
| Analytics | Figures and business observations | How this is measured per card and connection health disclosure | Existing values, explanations and sources preserved |
| Settings | Update business details and configuration destinations | Optional workspace setup disclosure | Same settings routes and authorization |

Native details/summary supports keyboard opening and closing without new state machinery. Existing focus classes and wrapped navigation retain narrow-screen usability. These are presentation changes, not authorization boundaries: filtering permissions still occurs through existing code, and directly visited routes still enforce their existing guards.

The shell has six catalog groups; the AI group is contextual, so ordinary broker screens show at most five before role filtering. Advanced destination links are not deleted. Intentional search for an advanced tool remains a valid way to enter that workflow.

Remaining review: composed specialist screens can contain their own tool palettes and dynamic service messages. Their actual role/state combinations require authenticated QA. This phase does not certify that every historical AI surface is contextual or that all advanced controls across all modules are hidden.
